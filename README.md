# CRSF2PPM

CRSF (Crossfire / ExpressLRS) to PPM converter for the **ESP32-C3**, with a
self-hosted web interface for channel mapping, failsafe and output setup.

The PPM output is generated by the ESP32-C3 RMT peripheral, so pulse timing is
hardware-accurate even while Wi-Fi is running. The firmware speaks CRSF over a
UART and emits a Betaflight-compatible PPM sum signal.

```
CRSF receiver TX ──► GPIO4 (UART1 RX) ──┐
CRSF receiver 5V ──► 5V                 ├── ESP32-C3 ── GPIO5 (RMT) ──► flight controller PPM input
CRSF receiver GND ─► GND ───────────────┘                     GND ────► flight controller GND
```

## Features

- CRSF input over UART: 420000 baud by default; 400000 and 115200 selectable.
- Classic PPM output: 1–16 channels, default 8; 22.5 ms frame; 400 µs pulse.
- Per-output channel mapping (any of the 16 CRSF channels to any PPM slot).
- Failsafe: preset values (default throttle slot 3 = 1000 µs) or hold-last.
- Polarity, frame period, pulse width, baud, pins and failsafe timeout configurable.
- Live web UI: channel bars, CRSF link statistics, mapping table, test mode.
- Wi-Fi access point `CRSF2PPM-XXXX` (default password `crsf2ppm`), or AP+STA.
- Config stored in NVS and reloaded on boot; mDNS at `crsf2ppm.local`.
- Serial console for bench diagnostics and a CRSF parser self-test.
- No external Arduino libraries; only the ESP32 core is required.

## Quick start

1. Flash the firmware (see [Build and flash](#build-and-flash)).
2. Power the board. It starts a Wi-Fi AP named `CRSF2PPM-XXXX`, where `XXXX` is
   derived from the ESP32's AP MAC address.
3. Connect a phone/laptop to that AP with the password `crsf2ppm` and open
   **http://192.168.4.1/** (or `http://crsf2ppm.local/`).
4. Wire the CRSF receiver and flight controller as shown above, then set the
   channel mapping, failsafe values and output timing in the web UI.
5. Use **Test mode** to sweep all outputs without a receiver. Verify with a
   servo or scope before connecting a flight controller.

The default AP password can be changed in the **Network** card. The web UI has
no login of its own, so use a strong WPA2 password if others share the area.

## Wiring

| Signal | ESP32-C3 pin | Notes |
|---|---|---|
| CRSF receiver **TX** | GPIO4 (UART1 RX) | Receiver TX, not RX. Configurable (valid C3 GPIO). |
| PPM output | GPIO5 | RMT TX; 3.3 V logic. Configurable. |
| Power | 5V / GND | Power the board from USB or a stable 5 V source. |
| Ground | GND | Receiver, converter and flight controller grounds must be common. |

Do not feed more than 3.3 V into a GPIO. ESP32-C3 GPIOs 11–17 are used by SPI
flash; GPIO18/19 are USB. The firmware only accepts GPIO0–10, 20 and 21, and
refuses to use the same pin for CRSF and PPM.

## Build and flash

Requires the ESP32 Arduino core 3.3.x (`esp32:esp32`). The project is an
Arduino sketch folder: `CRSF2PPM.ino` plus supporting `.cpp/.h` files.

```bash
arduino-cli compile \
  --fqbn "esp32:esp32:esp32c3:CDCOnBoot=cdc,FlashSize=4M,PartitionScheme=huge_app,UploadSpeed=921600" \
  .

arduino-cli upload -p COMx \
  --fqbn "esp32:esp32:esp32c3:CDCOnBoot=cdc,FlashSize=4M,PartitionScheme=huge_app,UploadSpeed=921600" \
  .
```

- `CDCOnBoot=cdc` makes `Serial` use the ESP32-C3 USB-Serial/JTAG port, so the
  serial console works over USB.
- `PartitionScheme=huge_app` gives 3 MB to the application; there is no OTA.
- If you use a board with a different flash size, change `FlashSize` and pick a
  suitable partition scheme. The binary is about 1.1 MB.

On Windows, `arduino-cli` may be bundled inside the Arduino IDE 2.x installation
(`...\Arduino IDE\resources\app\lib\backend\resources\arduino-cli.exe`).

## PPM format

The output follows the conventional PPM sum format decoded by Betaflight's
`RX_PPM` driver:

- A frame contains **N+1 pulses** for N output channels.
- The pulse width is fixed (default 400 µs); the **time between consecutive
  rising edges** encodes the channel value (800–2200 µs, nominal 1000–2000).
- The final interval is a long **sync gap** (>3 ms in this firmware; Betaflight
  treats any interval >2.7 ms as sync).
- The nominal frame period is 22.5 ms. If the sum of channel intervals plus a
  3 ms sync gap would exceed the configured period, the frame is extended
  automatically (relevant with many channels at extreme values).
- Polarity can be inverted (idle high) for receivers/FCs that require it.

Betaflight's PPM decoder supports up to about 12 channels. The firmware can
output up to 16, but use 8 (the default) for typical flight-controller PPM
inputs. Pulse timing comes from RMT hardware; the measured frame period includes
a small (~40–80 µs) software turnaround between frames.

## CRSF input

- UART: 8N1, default 420000 baud, on the configured RX pin.
- Parses `CRSF_FRAMETYPE_RC_CHANNELS_PACKED` (0x16) and
  `CRSF_FRAMETYPE_LINK_STATISTICS` (0x14); CRC8 is DVB-S2 polynomial 0xD5.
- Accepts the receiver/transmitter/FC CRSF addresses and resynchronises on
  garbage or bad CRC.
- Link statistics are shown in the web UI (RSSI, LQ, SNR). The converter is
  one-way: it does not send telemetry back to the receiver.

Channel conversion uses the standard mapping:
`µs = 1500 + (raw − 992) × 5 / 8`, clamped to 800–2200 µs.

## Failsafe

- If no valid RC frame is received for `failsafe_ms` (default 500 ms), the
  configured failsafe mode takes over.
- **Preset** (default): each output slot uses its configured failsafe value.
  Slot 3 (normally throttle in AETR order) defaults to **1000 µs**; all other
  slots default to 1500 µs.
- **Hold**: keep the last valid output values.
- Before the first valid CRSF frame, preset values are always used, even in
  hold mode.

Set failsafe values in the mapping table, and test the mode with the flight
controller's own failsafe checks before flight.

## Web interface

Open `http://192.168.4.1/` while connected to the device AP.

- **Live channels** — CRSF frame rate, PPM frame rate, RSSI/LQ/SNR, CRC errors,
  measured PPM period, channel bars and raw CRSF values.
- **Channel mapping** — number of PPM outputs, source channel per output, and
  per-slot failsafe value.
- **Output & failsafe** — frame period, pulse width, polarity, failsafe mode and
  timeout, CRSF baud.
- **Network** — AP/STA status, AP password, optional STA credentials, CRSF RX
  pin and PPM output pin.
- **Test mode** — generates a slow sweep on every output without a receiver.
- **Reboot** — restarts the converter.

Changing the CRSF/PPM pins, baud, AP password or STA credentials saves the config
and reboots automatically. Mapping, timing, polarity and failsafe changes apply
on the next PPM frame without a reboot.

### HTTP API

All responses are JSON. `POST /api/config` and `/api/test` use
`application/x-www-form-urlencoded`.

| Method | Path | Purpose |
|---|---|---|
| GET | `/` | Web UI |
| GET | `/api/status` | Live state: Wi-Fi, CRSF stats, raw/output channels, PPM stats, heap |
| GET | `/api/config` | Stored configuration (passwords are never returned) |
| POST | `/api/config` | Update configuration; omitted fields keep their current value |
| POST | `/api/test` | `on=1` / `on=0` toggles the output sweep |
| POST | `/api/selftest` | Feeds a synthetic CRSF frame plus a bad-CRC frame into the parser |
| POST | `/api/reboot` | Reboot the device |

Example:

```bash
curl http://192.168.4.1/api/status
curl -X POST -d "count=8&frame_us=22500&failsafe_mode=preset" \
     http://192.168.4.1/api/config
```

The self-test endpoint is for the bench only: it injects channel values
172, 236, … 1132 and increments the CRC error counter to prove that bad frames
are rejected.

## Serial console

USB CDC at 115200 baud (data rate is nominal for USB CDC). Commands are
line-based:

| Key | Action |
|---|---|
| `s` | Print status |
| `t` | Toggle test mode |
| `x` | Run the CRSF parser self-test |
| `r` | Reboot |
| `d` | Restore defaults and reboot |
| `?` | Help |

Boot and periodic logs include PPM frame rate/period, error counters, link
state and free heap. This is useful when Wi-Fi is not available.

## Configuration defaults

| Setting | Default |
|---|---|
| PPM outputs | 8 |
| Mapping | output 1→CRSF 1, … output 16→CRSF 16 |
| Failsafe values | 1500 µs; output 3 = 1000 µs |
| Failsafe mode / timeout | preset / 500 ms |
| Frame period / pulse width | 22500 µs / 400 µs |
| Polarity | normal (idle low) |
| CRSF baud / RX pin | 420000 / GPIO4 |
| PPM pin | GPIO5 |
| AP password | `crsf2ppm` |
| STA | disabled |

## Bench verification

The firmware in this repository was compiled and flashed to an ESP32-C3
(QFN32, rev v0.4, 4 MB flash) and verified on the bench:

- PPM runs at ~44 frames/s with a ~22.53 ms measured frame period and zero RMT
  errors; test mode produced a clean channel sweep.
- The CRSF parser self-test passes for a valid 16-channel frame and rejects a
  corrupted CRC frame.
- The web page, `/api/status`, `/api/config`, `/api/test`, `/api/selftest`, and
  `/api/reboot` were exercised; mapping CH3→output 1 produced the expected
  1068 µs from raw 300, and both preset and hold failsafe behaviour were
  observed.
- Configuration survived reboots via NVS.

Not covered in that session: a live CRSF receiver on the UART, oscilloscope
measurement of the PPM waveform, and joining an external STA network. Validate
those on your hardware before flight. PPM timing is generated in hardware but
the converter is not a certified safety device; always check failsafe and
output behaviour with the flight controller disarmed/props removed.

### Troubleshooting notes

- If the web UI loads slowly or stalls, the AP is 2.4 GHz and shares spectrum
  with the RC link. Try a different client, disable client Wi-Fi power saving,
  or move the device away from congested access points. The converter keeps
  running and PPM output is unaffected by HTTP stalls.
- If the AP is not visible, check that the board booted (serial log) and that
  the last configured AP password is known. `d` on the serial console restores
  defaults.
- If the PPM output does not drive the FC, check common ground, signal polarity,
  and whether the FC expects PPM on that input. Use test mode and a servo to
  verify the signal first.
- If CRSF is not detected, verify the receiver is in CRSF mode, its TX pad goes
  to the configured RX pin, and the baud matches. The web UI shows CRC/frame
  counters and link statistics.

## Security

The AP uses WPA2 with the configured password, but the web API itself has no
authentication. Anyone with the AP password can change settings. Do not expose
the AP to untrusted users. STA mode keeps the AP enabled for configuration.
